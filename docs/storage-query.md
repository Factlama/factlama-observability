# Storage and query API

`TelemetryStore` is a tenant-scoped port for spans/events and aggregate projection; `QueryRepository` reads tenant-filtered projections. ADR-009 selects PostgreSQL for MVP with migrations and separate logical tables/indexes for spans, reliability events and aggregates. No custom time-series engine is required. The dashboard calls query APIs only. Interaction content is outside this store by default.

Target read routes under `/v0.1`: `GET /ai/requests`, `/ai/traces/{trace_id}`, `/ai/evaluations/{evaluation_id}`, `/ai/overview`, `/ai/models`, `/ai/reliability`, `/ai/rag`, and `/ai/tools`. All require authenticated tenant scope, authorized project/application filters, bounded UTC `from`/`to`, stable sort and opaque cursor pagination where rows are returned. Trace detail includes linked evaluations by ID and explicit `PENDING|NOT_EVALUATED|AVAILABLE` state. Aggregate responses include window, sample count, units, currency, pricing version and null/unavailable status for missing measures. Queries must not expose existence across tenants; inaccessible IDs return 404. Error and pagination shapes follow the [shared contract](https://github.com/Factlama/factlama-architecture/blob/main/CONTRACTS.md#errors-and-pagination).

Retention is per tenant and data class. Deletion must remove source and derived projections, with documented lag. Indexes include tenant and time before high-cardinality IDs; row-level constraints or equivalent are a second guard behind application authorization. Query tests cover empty windows, cursor filter mismatch/expiry, time boundaries, missing evaluation, delayed event join, cross-tenant access, and aggregate correctness under duplicate telemetry.
