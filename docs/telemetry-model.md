# Telemetry contract v0.1

OpenTelemetry trace/span/resource concepts are the transport boundary. The [shared contract](https://github.com/Factlama/factlama-architecture/blob/main/CONTRACTS.md) defines `ReliabilityEvent` and `AITrace`. FactLama-specific attributes use the `factlama.*` namespace; map recognized OTel GenAI attributes into the query projection without erasing source attributes. Mapping version is recorded. Do not send raw prompt/response/evidence as span attributes by default.

Required after normalization: authenticated `tenant_id`, `project_id`, `application_id`, trace/span IDs for traced operations, operation type, start/end timestamps and status. Applicable AI attributes: provider/model/version, input/output/total tokens, latency, error class, price currency and pricing version, retrieval count and references, tool name/status/latency, interaction ID, evaluation ID, verdict, measured scores and evaluator/policy versions. Absence is distinct from zero. Cost is `UNAVAILABLE` when token usage or price version is unknown; derived costs record pricing source/version and calculation time. High-cardinality IDs remain query fields, not metric labels. Resource and extension attributes are allowlisted and size bounded.

An evaluation event may arrive before or after its trace. Correlate by tenant plus evaluation ID and applicable interaction/trace/span IDs; retain an unmatched event for a bounded reconciliation window. Never join solely on a user-controlled ID or across tenants. Duplicate events with the same `(tenant_id,event_id)` update no counters twice. A trace with no evaluation reports `NOT_EVALUATED` or `PENDING`, never PASS. Schema/semantic changes require golden event fixtures and a shared contract review.
